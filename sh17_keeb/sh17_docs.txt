sh17 is a 17 key custom 4x5 numpad with additional buttons above it. I handwired using 4 cols and 5 rows.

//Step 1. Open qmk msys and create a new keyboard
    Follow the prompts and naming guidlines (no caps, spaces are '_')


    Created a new keyboard called sh17
	Build command: qmk compile -kb sh17 -km default
	Project Location: C:/Users/mjenk/qmk_firmware/keyboards/sh17

	Now update the config files to match the hardware!

//Step 2. Figure out Column and row matrix. 

	col 0 = B2 //black wire to pin 16
	col 1 = B3 //blue wire to pin 14 
	col 2 = B1 //green wire to pin 15
	col 3 = F7 //red wire to pin 18/A0
	row 0 = D1 //brown wire to pin 2
	row 1 = D0 //green wire to pin 3
	row 2 = D4 //white wire to pin 4
	row 3 = C6 //blue wire to pin 5
	row 4 = D7 //yellow wire to pin 6

//Step 4. Create a keymap.

    Open keymap.c in VS_Code

    Configure the keymap to match what you want the layout to be. 
    Row 0 [S, A, LBRC, ESC]

            KC_S,   KC_A,   KC_LBRC,   KC_ESC,
            KC_KP_7,   KC_KP_8,   KC_KP_9,

//Step 5. Next create firmware
    in qmk msys compile the keyboard created

    qmk compile -kb sh17 -km default   //this builds a hex file in the qmk_firmware folder (sh17_default.hex).

// Step 6. Flash the firmware
    Open qmk toolbox

    Either drag and drop or open the hex file created in step 5.

    Flash the firmware.

Looking at the actual wiring, I realized that my (when looking from the bottom) left side was wired backwards from the rest of the key switches
and one of the diodes was no longer attached.

Option 1: to fix this is to desolder and rotate the keyswitch 180 degrees. Then, resolder the connections following the proper layout, or at
least the same as the rest of the switches. Then, resolder NEW diodes onto the keyswitchs, then double check the matrix, cols, and rows to make
sure everything is lined up properly between the GPIO pins, the col2row layout, the matrix, and make sure the keymap is configured properly. 

Then, open the qmk toolbox and flash the corrected firmware, to the corrected hardware, and debug from there.
